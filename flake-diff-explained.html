wisp.place · packaging change

the flake diff, in plain english

This change replaces the old Rust-oriented Nix packaging with a reproducible Bun build for wispctl, then gives Nix a normal package, an executable app, and a path to cached binaries.

package: wispctl 1.1.3 builder: bun2nix cache: wispplace.cachix.org verified: nix flake check

the short version

01

build the thing that actually exists

The repository CLI is Bun/TypeScript, so the flake now uses bun2nix instead of trying to compile a Rust binary that is no longer the CLI implementation.

02

make the monorepo installable

The CLI gets its own lockfile and generated dependency expression. Workspace links become local file: links for the isolated Nix build.

03

let users download results

The flake advertises the wispplace Cachix cache. CI still needs to build and push the derivation before users can substitute it.

what changed in flake.nix

inputs

The flake now brings in:

  • nixpkgs for the platform packages and standard Nix build environment.
  • flake-utils to expose the same outputs for each default system.
  • bun2nix to turn the Bun lockfile into fixed-output Nix dependencies.

the derivation

wispctl is built with bun2nix.mkDerivation. The source is the repository root, while bunRoot = "cli" tells the dependency hooks where the CLI manifest lives.

The root manifest and lockfile are renamed during postPatch. That prevents Bun from treating the entire monorepo as the install root while the standalone CLI lockfile is being used.

important build settings
bunInstallFlags = [
  "--frozen-lockfile"
  "--offline"
  "--linker=hoisted"
  "--backend=copyfile"
];

bunRoot = "cli";

bun build ./cli/index.ts \
  --outfile wispctl \
  --compile --minify \
  --sourcemap --bytecode

The build is offline and frozen: it must use the dependency data already captured in cli/bun.lock and cli/bun.nix.

the outputs users can consume

packages.default

The installable Nix package. Build it with nix build .#default; the binary ends up at result/bin/wispctl.

apps.default

The runnable flake app. Invoke it with nix run . -- --help or from a remote flake reference.

devShells.default

A small development environment containing Bun and bun2nix for working on the packaging setup.

metadata: the meta blocks describe the package and identify wispctl as its main program. They do not contain binaries, secrets, or cache data.

These generated files are the reproducibility layer, not hand-written application logic:

why package manifests changed

unpinned Bun type packages

References such as "latest" became explicit ranges such as "^1.3.14". This lets the lockfile describe a stable dependency graph instead of asking a sandboxed build to resolve a moving tag.

workspace links → local files

The CLI and a few local packages use paths such as file:../packages/@wispplace/lexicons. That is intentional for this standalone build: the package source is present in the flake source tree, so Bun can resolve it without a live workspace install.

scope note: the old flake exposed explicit Linux and macOS target packages based on Rust cross-compilation. The new flake exposes the native package for each system evaluated by eachDefaultSystem; separate CI builds are needed if you want every platform’s binary pre-populated in Cachix.

how Cachix fits in

what is already configured

  • Substituter: https://wispplace.cachix.org
  • Public signing key: committed in flake.nix
  • Cache name: wispplace

That tells Nix where it may download a matching store path from.

what still has to happen

  1. Add a Tangled spindle workflow at .tangled/workflows/build-wispctl.yml.
  2. Configure the repository’s CACHIX_AUTH_TOKEN pipeline secret.
  3. Let the workflow run nix build .#default and push ./result to Cachix.
  4. Run nix build .#default on each desired platform.

Until CI pushes a result, users can still build locally; the cache cannot substitute an artifact that has never been uploaded.

user command, after the cache has been populated
nix run --accept-flake-config \
  'git+ssh://git@knot.gaze.systems/nekomimi.pet/wisp.place-monorepo'

Nix asks users to explicitly trust flake-provided substituter settings. That is a security feature, not a build failure.
